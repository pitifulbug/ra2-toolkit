# ra2-toolkit

这是基于原 `ra2_background_crate_picker` 项目修改的后台自动捡箱子程序。它读取游戏内部的当前选择列表与箱子数组，向游戏事件队列提交单位任务，不读取鼠标位置，也不会移动或占用真实鼠标。

## 适配程序

下列三个程序运行任意一个均可连接：

- `gamemd.exe`：SHA-256 `3E81A61775D2745D1DABE397325EF663CD994FFC194DA4E998E3BF5D2D308600`
- `gamemd-ares.exe`：支持 `1.11` 原始版及保持关键布局不变的兼容补丁组合
- `gamemd-spawn.exe`：支持 `1.11-CnCNet-patch-213aa6b` 及保持关键布局不变的兼容补丁组合

已知哈希会直接通过；遇到客户端生成的新哈希时，程序会继续校验文件大小、文件版本、32 位 PE 格式、映像基址、三组捡箱核心指令以及运行时内存结构。全部一致才会连接。

战役、遭遇战、局域网和互联网模式均可连接，不再主动限制联网模式。

运行时允许 `HouseArray` 包含最多 10 个条目，用于兼容八个可玩阵营加中立/特殊阵营；当前玩家仍必须能在前八个可玩阵营槽位中找到。

## 使用方法

1. 先启动红警并进入需要使用的对局。
2. 运行 `release\ra2-toolkit.exe`，同意管理员权限提示。发布版已内置 .NET 运行时，目标电脑不需要另装 .NET。
3. 在游戏中框选一个或多个己方步兵、车辆或其他可移动单位。
4. 按 `F5` 开始自动捡箱子。
5. 按 `F6` 暂停；暂停后可重新框选单位，再按 `F5` 重新开始。
6. 按 `F10` 退出辅助程序。

按 F5 时，程序会从游戏的 `FootClass` 可移动单位列表中校验并锁定当前全部有效选择。之后你可以正常移动鼠标、切换窗口或选择其他单位，自动捡箱子不会改变已锁定对象，也不会干扰鼠标操作。

程序会打开控制台窗口，显示连接结果、使用教程、当前状态、已锁定单位、箱子分配、待命和错误信息。窗口标题会实时显示单位总数、正在捡箱数和待命数。

游戏左上角文字注入仍保持完全关闭，所有提示只显示在辅助程序自己的控制台窗口中。如果 F5 时没有选中有效己方单位，控制台会提示重新框选。

## 自动行为

- 每 15 毫秒由同一个后台调度器读取一次箱子列表，并为每个锁定单位维护独立状态。这样可避免多个系统线程同时写入游戏共享事件队列，但多个单位在游戏中仍会同时行动。
- 自动为各单位分配不同箱子；当箱子少于单位数量时，多出的单位会在安全位置待命。
- 每个单位优先选择离自己最近且尚未被其他单位认领的箱子，并定期重新下达移动任务。
- 单位对当前箱子连续 3 秒没有移动时，会立即释放该箱子的认领并改派其他目标；该单位会在 8 秒内跳过这个箱子，但其他单位仍可尝试。
- 8 秒冷却结束后允许原单位再次尝试，避免箱子因为短暂堵路而被永久忽略。
- 单位状态偶发读取异常时不会立即永久删除：程序先暂停该单位并释放其箱子认领，2 秒内恢复就自动重新加入调度；连续 2 秒仍无效才判定为阵亡或离场。
- 任一单位到达箱子格后，会在同一轮扫描中立即寻找下一个箱子，不设置捡箱后的等待时间。
- 同一个游戏箱子槽位被复用于新坐标时，会按“槽位＋坐标”识别为新箱子并立即下达任务。
- 没有箱子时前往当前玩家的基地中心；没有有效基地位置时原地警戒。
- 前往基地期间连续 10 秒没有移动进展，会判定该位置不可达并改为原地警戒。
- 新箱子出现后立即结束待命并继续收集。
- 单个单位阵亡、被删除或不再属于当前玩家时只移除该单位；全部锁定单位均失效时自动停止。

## 限制与验证边界

- 整文件哈希不同不再单独构成拒绝理由；关键指令、文件布局或运行时内存结构有任何一项不匹配时仍会拒绝写入。
- 箱子选择使用直线距离；动态堵路由游戏寻路处理，长期无移动时程序会定期重发目标。
- 已完全移除 `MessageListClass` 游戏文字注入、远程线程创建和游戏文字缓冲区写入代码；控制台提示不写入游戏内存。
- 游戏被其他窗口遮挡时程序仍可工作；如果最小化会暂停单机模拟，则恢复游戏后继续。

## 源码构建

源码构建需要 .NET 10 SDK；普通使用者只需要 `release\ra2-toolkit.exe`：

```powershell
dotnet publish .\ra2-toolkit.csproj -c Release -o .\release
```

项目已经配置为 `win-x64` 自包含单文件发布，输出目录中只需要保留 `ra2-toolkit.exe`。
